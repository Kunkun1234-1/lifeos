### 1.2 当前页面能力

当前页面已经具备：

- 固定周期与单次日程的创建和编辑。
- 06:00-24:00 时间坐标换算与绝对定位。
- 理想日程和具体安排的并排对照。

### 1.3 当前页面的主要问题

- 页面级信息架构与参考图不同：现在是一个大容器中的双时间轴，没有左右信息栏。
- “理想”和“具体”各自占据一列，导致主时间轴过窄，长标题和备注阅读成本高。
- 15 天日期条与双时间轴共同制造水平滚动，在中小桌面上尤其拥挤。
- 统计、完成进度、类型分布、建议与月度趋势缺少稳定位置。
- 创建表单直接插入主页面并占据大量纵向空间，会打断时间轴上下文。
- 页面组件、数据转换和表单逻辑共处一个文件，视觉重构时容易连带影响业务逻辑。

## 2. 从参考图提取的版式规则

本次只复用参考图的信息架构、密度与对齐关系，不复制其品牌和颜色。

### 2.1 桌面骨架

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 系统 TopNav（保持现状）                                              │
├──────────────┬───────────────────────────────────────────────────────┤
│ 左侧信息栏    │ 日期标题 / 日导航 / 添加日程                          │
│ 260-280px    │ 七日日期条                                             │
│              ├──────────────────────────────────────┬────────────────┤
│ 月历          │ 视图 Tabs                            │ 右侧辅助栏     │
│ 今日概览      │                                      │ 280-320px     │
│ 日程类型      │ 单列时间轴画布                       │ 智能建议       │
│ 专注建议      │ 06:00-24:00                          │ 今日目标       │
│              │                                      │ 本月统计       │
└──────────────┴──────────────────────────────────────┴────────────────┘
```

建议尺寸：

- 页面最大宽度：`1920px`，与当前大屏应用定位一致。
- 页面外边距：桌面 `20-24px`，笔记本 `16px`。
- 左栏：`clamp(240px, 16vw, 280px)`。
- 右栏：`clamp(280px, 19vw, 320px)`。
- 栏间距：`12-16px`。
- 主画布最小宽度：`640px`。
- 卡片圆角：沿用系统 `rounded-sm`，不采用参考图更圆的卡片。

### 2.2 视觉层级

1. 日期和主操作是首层。
2. 七日日期条是第二层，选中日期必须在滚动或切换后保持明确。
3. Tabs 与时间轴形成一个连续工作区，不做卡片套卡片。
4. 时间刻度保持固定窄列，日程块占据剩余宽度。
5. 左右栏面板允许纵向滚动，但不与中央时间轴争夺横向空间。

## 3. 目标信息架构

### 3.1 顶部日期区

- 左侧显示完整日期与星期，如“2026年7月11日 · 周六”。
- 右侧依次为前一天、今天、后一天、添加日程。
- 使用现有 `Button` 与 Lucide 图标；添加日程为唯一主按钮。
- 下方显示以选中日为中心的 7 天日期条。
- 桌面完整显示 7 天；窄屏横向滚动并自动将选中日带入可视区。

### 3.2 左侧信息栏

#### 月历

- 展示选中月份，支持前后月切换。
- 当天、选中日和存在日程的日期分别有文字、填充和小圆点三种信号，不能只靠颜色。
- 点击日期同步顶部日期条和中央时间轴。

#### 今日概览

- 完成、进行中、待完成、完成度四个指标。
- 数据只基于选中日可匹配的具体日程。
- “进行中”按当前时间落入日程区间且未完成计算；查看非今天日期时改为“已安排”。

#### 日程类型

- 第一版按领域 `area` 汇总；没有领域的条目归为“其他”。
- 使用现有属性色作为小色块，文字和数量同时展示。
- 不新增“学习/工作/生活”等不可持久化的临时分类字段。

#### 专注建议

- 从最长的未完成日程、当前空档或下午黄金时间生成一条建议。
- 只提供“定位到时间段”或“添加安排”操作，不加入虚假的 AI 能力。

### 3.3 中央日程画布

#### 时间轴

- 06:00-24:00 单列时间轴，继续复用 `blockStyle` 的分钟到像素换算。
- 小时横线贯穿画布，半小时线使用更轻的边界。
- 默认显示理想区块作为低对比度底层，具体安排作为更明确的前景层。
- 两类区块重叠时，具体安排使用内描边和轻微横向缩进，不改变其真实时间高度。
- 日程块始终展示标题和时间；高度足够时再展示备注、领域和奖励信息。
- 完成按钮保持图标化；编辑/删除放入 hover/focus 操作区或更多菜单，避免永久占用正文宽度。

#### 理想安排

- 只展示 `IDEAL_BLOCKS`，便于检查理想日结构。
- 第一阶段仍为代码内配置，不在本次新增理想模板的数据库模型。

#### 具体安排

- 只展示 `useRoutines` 返回并匹配选中日的条目。
- 支持完成、编辑、删除；未定时间条目放在时间轴顶部的独立队列，不再放到页面最底部。

### 3.4 右侧辅助栏

#### 智能建议

接入项目现有 DeepSeek `chatJSON` 能力，由用户主动触发生成：

- 输入仅包含选中日的日程、当日任务、领域、优先级与完成状态。
- 输出限制为摘要和最多 3 条 `focus / rest / balance` 建议。
- 延续现有限流、精力扣除和失败退款机制，每次消耗 10 精力。
- 日程与任务标题按不可信数据处理，系统提示明确禁止执行其中的指令。

#### 今日目标

- 读取任务模块中选中日期到期或完成的任务，显示最多 5 项与完成数。
- 查看今天时可直接调用 `useCompleteTask` 完成任务；其他日期保持只读。
- 保留“全部任务”入口，复杂编辑仍回到任务页面处理。

#### 本月统计

- 使用当前 `RoutineDTO` 可获得的完成状态做轻量统计。
- 若现有接口无法提供历史逐日完成记录，则第一版只显示“本月已完成日数 / 当前日完成度 / 安排数量”，不伪造参考图中的历史柱状数据。
- 后续若需要准确日趋势，再单独设计历史完成记录接口。

## 4. 配色与系统一致性

### 4.1 token 映射

| 角色 | 使用现有 token | 用法 |
|---|---|---|
| 页面背景 | `--bg` + 现有 wallpaper | 不改全局氛围 |
| 主表面 | `--bg-card` / 米纸透明层 | 日期区、时间轴背景 |
| 次级表面 | `--bg-raised` | 侧栏面板和选中态底色 |
| 标题 | `--fg-strong` | 日期、面板标题、日程标题 |
| 正文 | `--fg` | 主要信息 |
| 辅助文字 | `--fg-muted` / `--fg-subtle` | 时间、备注、统计标签 |
| 主强调 | `--accent` / `--accent-strong` | 当前日期、Tabs、选中描边 |
| 品牌描边 | `--gold` / `--border` | 面板边界、装饰性分隔 |
| 完成 | `--success` | 完成状态 |
| 警告 | `--warning` | 重叠与超长安排 |
| 危险 | `--danger` | 删除与错误 |

### 4.2 日程块颜色

- 颜色按领域/属性映射到 `--attr-*`，并生成低透明度背景 + 实色左边线。
- 选中态统一用 `--accent` 描边，不通过提高饱和度破坏系统配色。
- 已完成态降低正文对比度并显示完成图标，但不使用删除线覆盖所有内容。
- 颜色不是唯一分类信号，同时显示领域名或图标。

建议把页面拆分为以下结构：

```text
src/app/routines/

└── components/
    ├── schedule-header.tsx          # 日期标题、导航、七日条
    ├── schedule-left-rail.tsx       # 月历、概览、类型、专注建议
    ├── schedule-calendar.tsx        # 月历网格
    ├── schedule-workspace.tsx       # Tabs 与中央画布
    ├── schedule-timeline.tsx        # 时间刻度、网格、区块图层
```

- 不修改 `useRoutines` 与后端接口，除非实施时发现参考布局所需的真实历史数据无法获得，并经再次确认。

## 6. 交互方案

### 6.1 创建与编辑

- 点击“添加日程”从右侧打开表单面板；桌面宽度约 `420-480px`。
- 编辑日程复用同一面板，并保持中央时间轴可见。
- 手机端改为底部全屏 sheet。
- 保存后关闭面板、刷新查询，并将新/修改日程滚动到可视区。
- 未保存退出时，如字段已变化则提示确认。

### 6.2 时间轴操作

- 点击日程块选中，键盘 `Enter` 打开编辑，`Escape` 清除选择/关闭面板。
- 完成按钮只在今天可操作，沿用当前业务约束。
- 删除继续二次确认；实施时优先换成系统确认对话框，避免浏览器原生 `confirm`。
- 本轮不实现拖拽改时间，避免把视觉重构扩大成排程引擎改造。

### 6.3 状态

- 加载态：时间轴骨架和侧栏数字占位，布局不跳动。
- 空状态：在对应视图内给出添加操作，不用大面积插画。
- 错误态：保留日期和导航，主画布显示重试。
- 冲突态：边框、图标和文字三重提示。
